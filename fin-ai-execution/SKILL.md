## 🌐 数据获取方式（统一数据层 · 零 API Key）

本项目**不依赖任何私有连接器**。所有行情/基本面数据来自仓库内置的统一数据层：

```bash
# 语法：python shared/fin_data.py <端点> <股票代码>
python shared/fin_data.py quote    sh600519     # 实时行情（含 PE/PB/市值/换手率）
python shared/fin_data.py kline    sh600519 --days 250
python shared/fin_data.py finance  sh600519     # 主要财务指标（8 期）
python shared/fin_data.py news     sh600519     # 最新新闻
python shared/fin_data.py list                  # 查看全部端点
```

| 数据通道 | 覆盖范围 | 需要 Key？ |
|---|---|:---:|
| **L1 公开数据源**（默认，零依赖） | 行情 / K线 / 技术指标 / 财务 / 股东 / 新闻 / 指数 / 板块 | ❌ |
| **L2 AKShare**（可选 `pip install akshare`） | A股深度：龙虎榜 / 融资融券 / 筹码分布 / 分红 / 北向资金 | ❌ |
| **L3 yfinance**（可选 `pip install yfinance`） | 港美股深度数据 | ❌ |

> **数据诚实原则（硬性）**：每次调用返回 `status` 字段 —— `ok` / `degraded` / `unavailable`。
> 凡是 `degraded` 或 `unavailable` 的字段，**必须在报告中显式披露数据来源状态**，
> **禁止**用估算值静默填充。宁可给出「该指标不可得」的专业结论，也不编造数字。

# 普惠金融-交易执行官 (fin-ai-execution) v3.0

## 用途

「普惠金融数字员工团队」中的**交易执行官**角色，对标真实基金的"交易部"。
v3.0 升级：**接入公开数据源 模拟撮合（本地 paper trading） 真实模拟交易**，让方案不再停留在纸面。

## v3.0 升级亮点

| 维度 | v1/v2 纸面版 | **v3.0 真实模拟 + 算法引擎** |
|------|------|------|
| 下单方式 | 输出文字建议 | **模拟撮合（本地 paper trading） 真实模拟** |
| 冲击成本 | 公式估算 | **基于实时盘口 + 历史波动率** |
| 拆单策略 | TWAP 单一 | **+ VWAP + POV + Iceberg** |
| 微结构 | 不支持 | **分时盘口 + 微观流动性分析** |

## 工作流程（5 步 · v3.0）

### Step 1 · **接收交易指令**
- 接收 fin-ai-portfolio 调仓清单 / fin-ai-crisis 减仓方案
- 输出：动作清单（每只股：买/卖/数量/方向/紧急度）

### Step 2 · **冲击成本估算**（v3.2.0 脚本化）
对每个动作：
- 调 `fin_data.py quote` 拿实时盘口（买卖价差）
- 调 `fin_data.py kline` 算 20 日历史波动率与日均成交额
- **必须运行** `python scripts/impact_cost.py --order-value 5000 --adv 120000 --daily-vol 0.0136`（平方根冲击模型，禁止手算）
- **`--daily-vol` 必须是【日】波动率**（如 0.0136）。从 `fin_data.py kline` 算出的 20 日年化波动率（如 0.212）**必须先除以 √244≈15.62**，否则结果放大 15.6 倍
- 脚本输出：冲击成本 bps、参与率校验（≤10% 日均成交额）、建议拆单份数与算法选择、系数 `impact_coef_used`
- 模型：`Δp/p = Y · σ_日 · √(Q/ADV)`，`Y` 默认 **0.33**（永久冲击口径），可用 `--impact-coef` 校准，典型区间 0.3~1.0

> **🐛 v3.3.0 修复：冲击成本量纲错误（数值放大 100 倍）**
> 旧版 `impact_bps = 33 × vol × sqrt(participation) × 10000`，把 0.2% 的合理冲击算成
> **2020 bps（20%）**，任何订单都会被判定为成本失控。v3.3.1 将系数显式改写为小数口径
> `Y=0.33`（`Δp/p` 直接为小数，×10000 转 bps），**数值结果与 v3.3.0 一致但量纲可解释**。

> **🐛 v3.3.1 修复：日波动率缺少合理性校验**
> 旧版对 `--daily-vol` 只校验 >0，误传年化波动率（如 0.212）会照单全收，
> 冲击成本被放大 15.6 倍（11.6 bps → 181 bps）且不报错。
> 现在：`>0.10` 输出 `vol_warning` 并给出「年化→日」换算提示；`>0.30` 直接拒绝。
- **前置检查**：先调合规专员 Step4.5 可执行性接口（停牌/跌停封板/流动性），被 block 的标的不得进入下单清单

### Step 3 · **拆单策略选择**（依据 impact_cost.py 算法篮子）

v3.4.1 起 `impact_cost.py` 一次给出 **5 个候选算法**的横向对比，含拆分数、每笔金额、估算冲击、
相比一次性下单的节省、执行时长、择时风险与取舍说明，并给出推荐（`recommended_algo` + 理由）。

```bash
python scripts/impact_cost.py --order-value 2000 --adv 1329400 --daily-vol 0.028
python scripts/impact_cost.py --order-value 150000 --adv 400000 --daily-vol 0.025 --horizon-hours 2
```

| 算法 | 逻辑 | 适用 |
|---|---|---|
| **TWAP**（时间加权） | 把订单均匀分布在指定时段 | 节奏均匀可预测；放量时段会错失流动性 |
| **VWAP**（成交量加权） | 跟随市场成交量分布 | 贴合真实量能、隐蔽性好；依赖日内量能预测 |
| **POV**（成交量比例） | 保持固定参与比例（上限 10%） | 自动跟随活跃度；执行时长不可控 |
| **Iceberg**（冰山） | 单笔小量多次、隐藏挂单量 | 暴露最小、适合隐蔽建仓；成交确定性最低 |
| **Sniper**（狙击） | 等价格触发时一次性成交 | 最快、无择时风险；一次性冲击最大且暴露意图 |

- **必须引用脚本给出的 `assumptions`**：模型为「总冲击 = 永久冲击 + 临时冲击/√N」，
  临时占比默认 40%（可调 `--temp-share`，合理区间 0.30~0.50）。
  永久冲击不随拆单次数摊薄——这是**拆单收益递减**的根因，报告中必须说明，避免让观众误以为拆得越细越好。

### Step 4 · **模拟交易**（v3.0 核心新增，v3.2.0 加人工确认闸门）
- **人工确认闸门（默认开启）**：参数 `auto_confirm` 默认 `false`——下单前展示订单清单（标的/方向/数量/算法/预估冲击成本），用户确认后才调 `模拟撮合（本地 paper trading）`；审计日志记录确认过程
- 调 `模拟撮合（本地 paper trading）`：
- 创建模拟卖出单
- 创建模拟买入单
- 输出模拟账户当前持仓
- 输出当日模拟 PnL

### Step 5 · **执行报告**
- 模拟成交价格 vs 当前价
- 各拆单策略的执行效果对比
- 推荐实盘时使用的策略

## 输出
