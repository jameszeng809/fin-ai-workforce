## 🌐 数据获取方式（统一数据层 · 零 API Key）

本项目**不依赖任何私有连接器**。所有行情/基本面数据来自仓库内置的统一数据层：

```bash
# 语法：python shared/fin_data.py <端点> <股票代码>
python shared/fin_data.py quote    sh600519     # 实时行情（含 PE/PB/市值/换手率）
python shared/fin_data.py kline    sh600519 --days 250
python shared/fin_data.py finance  sh600519     # 主要财务指标（8 期）
python shared/fin_data.py news     sh600519     # 最新新闻
python shared/fin_data.py list                  # 查看全部端点
```

| 数据通道 | 覆盖范围 | 需要 Key？ |
|---|---|:---:|
| **L1 公开数据源**（默认，零依赖） | 行情 / K线 / 技术指标 / 财务 / 股东 / 新闻 / 指数 / 板块 | ❌ |
| **L2 AKShare**（可选 `pip install akshare`） | A股深度：龙虎榜 / 融资融券 / 筹码分布 / 分红 / 北向资金 | ❌ |
| **L3 yfinance**（可选 `pip install yfinance`） | 港美股深度数据 | ❌ |

> **数据诚实原则（硬性）**：每次调用返回 `status` 字段 —— `ok` / `degraded` / `unavailable`。
> 凡是 `degraded` 或 `unavailable` 的字段，**必须在报告中显式披露数据来源状态**，
> **禁止**用估算值静默填充。宁可给出「该指标不可得」的专业结论，也不编造数字。

# 普惠金融-主理人 (fin-ai-orchestrator) v3.0

## 用途

「普惠金融数字员工团队」中的**主理人**角色，对标真实基金的"CIO 首席投资官"。
v3.0 核心升级：**圆桌讨论机制**——把 v1.0.0 的"分诊+汇总"升级为 v3.0 的
"调度 → 收集 → **圆桌讨论**（3 轮交叉质疑/互评/主理人综合） → 决策简报"。

## v3.0 升级亮点

| 维度 | v1/v2 单线汇报版 | **v3.0 圆桌讨论版** |
|------|------|------|
| 协同方式 | 调度 → 等结果 → 汇总 | **调度 → 收集 → 圆桌 3 轮 → 决策** |
| 分歧处理 | 不暴露 | **显式标注 + 主理人裁决** |
| 不确定性 | 单点估值 | **蒙特卡洛分布 + 群体共识度** |
| 决策可解释性 | 黑盒 | **可追溯到具体员工 + 具体分歧点** |
| 模拟决策 | 静态规则 | **可被人类 PM 反向质询** |

## 圆桌讨论机制 ★（v3.0 核心创新）

### 三轮圆桌会议

#### 第 1 轮 · 交叉质疑（Cross-Challenge）
- 每个员工的报告都暴露给其他员工查看
- 算法：识别"假设冲突"和"结论冲突"
- 例：
  - 研究员："茅台估值 ¥1087（偏低估）"
  - 风控官："组合消费集中度 50% > 30% 阈值（高风险）"
  - 议程："研究员认为有投资价值，风控认为组合已超配——谁能说服谁？"

#### 第 2 轮 · 员工互评（Peer-Review）
- 每个员工对他人的报告打分：
  - 研究员：评估风控官的"风险量化方法论"
  - 风控官：评估研究员的"估值假设合理性"
  - 投研经理：评估两者的"对组合的影响"
- 输出：每员工 1-5 星 + 评语
- **v3.2.0 弃权规则**：数据不足的员工输出 `abstain: true`（附理由），其评分不参与共识计算（对标 ai-hedge-fund：弃权不稀释他人观点），并在纪要中列为"缺席视角"

#### 第 3 轮 · 主理人综合（Orchestrator Synthesis，v3.2.0 公式化，v3.3.0 脚本化）
- **共识度评分改为可复现公式**（读 `data/scoring.json`，禁止 LLM 拍脑袋）：
  `consensus_score = 0.4×互评一致性(1-标准差/均值) + 0.3×分歧解决率 + 0.3×数据一致性`
  数据一致性 = 各员工引用同一指标偏差 <1% 的比例
- **v3.3.0 强制：必须运行脚本，禁止 LLM 心算**（弃权员工的评分不传入即自动实现"不稀释"）：

```bash
python scripts/consensus.py --peer-scores 4,4,5,3 --disputes-total 5 --disputes-resolved 4 --data-consistency 0.9
```

脚本输出：三个分项数值 + `consensus_score` + `uncertainty`(low/medium/high) + `unresolved_disputes`。
已解决分歧数 > 总分歧数、互评非 1-5 星等异常输入会直接报错，杜绝编造共识度。
- 主理人综合输出：
  - 团队一致性分数（consensus_score，公式计算，附各分项数值）
  - 显式分歧点（disputes: list，含未解决的）
  - 不确定性量级（uncertainty: low/medium/high）
  - 主理人立场（orchestrator_stance: string）
  - 最终决策建议（final_recommendation）
- **主理人产出目标权重后必须交风控官硬夹逼**（单票10%/行业30%，"Conviction requests, risk disposes"），夹逼结果不可自行覆盖

## 工作流程（6 步 · v3.0 升级）

### Step 1 · 任务解析
- 接收自然语言任务
- LLM 意图识别 → 场景模板

### Step 2 · **场景模板匹配**（v3.2.0：9 个模板 + 自定义）
- 模板 A/B（单股/组合标准分析）+ **模板 C：私募级组合管理全流程（v3.2.0 新增）** + **模板 D：策略回测（v3.2.0 新增）** + 自定义
- 模板决定调度哪些员工 + 并行/串行

**模板 C · 私募级组合管理 DAG（v3.2.0）**——回答"给我 20 只股/一个行业，像真私募一样管理"：

| 步骤 | 负责员工 | 内容 |
|------|---------|------|
| 1 宏观配置 | quant Step0 | 美林时钟象限 → 股/债/现金基准比例 |
| 2 行业轮动 | quant Step0.5 | 超配 3 行业 / 低配 3 行业 |
| 3 个股筛选 | quant Step6 | 三级漏斗 → 20 只候选池（支持给清单/给行业/给 watchlist 三种输入） |
| 4 组合优化 | quant Step4 | 20 只具体目标权重（Markowitz+风险平价对照） |
| 5 深度校验 | researcher | 对前 5 大权重股出 DCF/蒙特卡洛深度报告 |
| 6 **风控夹逼** | **risk Step6.5** | 硬性上限，被夹份额归现金，分析师无权覆盖 |
| 7 执行模拟 | execution | 合规检查 → impact_cost → 人工确认 → paper trade |
| 8 绩效复盘 | portfolio Step9 | 下期自动执行，结果回注圆桌（学习闭环） |

**模板 D · 策略回测 DAG（v3.2.0）**——回答"这些建议历史上灵不灵"：
- 并行调度：quant Step7（策略/因子级回测）+ portfolio Step10（组合调仓建议序列回测）
- 汇总输出一页结论：策略 vs 组合 vs 基准三线对照 + 回测假设声明（SimBroker 无滑点）
- 回测结果自动写入 `reviews/`，下轮圆桌自动引用

### Step 3 · **调度员工执行**（v3.2.0 优化）
- 并行调度（场景 A/B 的独立步骤并行；模板 C 按上表 DAG 串并行混合）
- **进度限制（v3.2.0 修正）**：以"步骤数 + 重试次数"限制，不再以秒数硬限（LLM 单次调用常超 30 秒，秒级时间盒不现实）；每员工最多重试 1 次
- **降级不崩盘（v3.2.0）**：某员工超时/失败 → 标记"缺席视角"继续圆桌，纪要中显式披露缺失了哪个视角，禁止因单点失败中止整场
- 收集团队作战包 Signal 卡 → **运行 `scripts/validate_package.py` 校验，FAIL 打回重跑一次，再 FAIL 则缺席处理**

### Step 4 · **圆桌讨论**（v3.2.0：4 轮 = 对抗 + 质疑 + 互评 + 综合）
- 第 0 轮 Bull/Bear 对抗 → 3 轮：质疑 → 互评 → 综合（共识度公式化）
- 输出：决策简报 JSON（Signal 卡 + 共识度分项数值）

### Step 5 · **决策可解释性输出**
- 每个决策都有"为什么"（指向具体员工分歧）
- 每个建议都有"谁能反驳"（附带反方观点，Bull/Bear 交锋记录自动归档）

### Step 6 · **决策简报 HTML**
- 圆桌会议纪要（含第 0 轮对抗记录）
- 跨场景联动（如场景A决策触发场景B监控）
- **（v3.2.0）复盘回顾块**：读 `../fin-ai-portfolio/reviews/` 最近一期 review，注入"上期建议准确率 + 误差来源"，作为本轮假设修正依据（学习闭环）
- 一页纸人话版（≤200 字）

### Step 7 · **CycleRecord 审计账本**（v3.2.0 新增，对标 ai-hedge-fund run_cycle）
每场圆桌输出完整审计记录 `fin-ai-orchestrator/cycles/cycle_{date}.json`：
`数据快照 hash → 各员工 Signal 卡 → Bull/Bear 交锋记录 → 分歧与裁决 → 夹逼前后权重 → 最终决策 → 引用的历史复盘`
→ 任何决策可一键回放"当时看到了什么数据、谁说了什么、为什么这么裁"

- 圆桌讨论的"分歧检测"基于 LLM，可能漏掉某些精细分歧

- 输出应视为"AI 团队的建议"，仍由人类 PM 最终决策
